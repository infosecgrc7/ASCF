# راهنمای انتشار در گیت‌هاب

[English](PUBLISHING.md) · [بازگشت به راهنمای فارسی](../README.fa.md)

مخزن فعلی پروژه [infosecgrc7/ASCF](https://github.com/infosecgrc7/ASCF) است. اسکریپت‌های بسته‌بندی فقط محلی عمل می‌کنند و مخزن، push یا انتشار راه دور ایجاد نمی‌کنند.

## مشخصات مخزن

نام اولیهٔ پیشنهادی بسته scf-mapping-toolkit بود؛ مخزن فعلی ASCF نام دارد.

توضیح پیشنهادی:

> ابزار نگاشت الزامات به SCF با شواهد اهداف ارزیابی، پشتیبانی ترجمهٔ فارسی، ردیابی منبع، فیلتر سخت‌گیرانهٔ واژگان و خروجی Excel بررسی‌شده.

موضوع‌های پیشنهادی: scf، strm، grc، cybersecurity، control-mapping، assessment-objectives، persian، translation، compliance.

README.md صفحهٔ اصلی و README.fa.md راهنمای فارسی است. حقوق کد محفوظ است و پروژه نباید متن‌باز معرفی شود. تا زمانی که مالک صریحاً تصمیم دیگری نگرفته، الگوی مجوز MIT یا Apache انتخاب نکنید.

## پیش از بارگذاری یا به‌روزرسانی

1. ZIP نهایی را در پوشهٔ جدید استخراج کنید؛ پوشهٔ کاری پیرامون آن را بارگذاری نکنید.
2. وابستگی‌ها و آزمون‌ها را اجرا کنید:

~~~bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -q
~~~

3. بررسی انتشار را اجرا کنید:

~~~bash
python scripts/audit_release.py
~~~

این بررسی پیوندهای محلی مستندات، حدود دادهٔ عمومی، الگوهای مسیر شخصی و حساب و در صورت وجود manifest، اثر انگشت فایل‌ها را بررسی می‌کند. جایگزین ممیزی جامع امنیتی نیست.

4. فرمان‌های validate، build-xlsx و check-xlsx نمونهٔ ساختگی را مطابق [راهنمای استفاده](USAGE.fa.md) اجرا کنید. نمونهٔ عمومی باید ساختگی بماند.
5. وجود LICENSE با عبارت all rights reserved و THIRD_PARTY_NOTICES.md را بررسی کنید. ورودی واقعی، ترجمه‌های داده‌ای SCF و متن کامل کتاب‌ها وارد انتشار نشوند.
6. عمومی یا خصوصی بودن مخزن و متن گردش‌کار آزمون را بررسی کنید. برای ادعای موفقیت آزمون راه دور، اجرای واقعی باید موفق باشد.

## بارگذاری

در بارگذاری وب، محتوای پوشهٔ استخراج‌شده را انتخاب کنید. برای Git، همان پوشهٔ استخراج‌شده را مخزن کنید و فقط فایل‌های ممیزی‌شده را ثبت و به مقصد ارسال کنید. .gitignore را حفظ کنید. پوشهٔ اصلی کار که local-data دارد نباید به‌صورت یکجا ثبت و ارسال شود.

اگر از GitHub CLI استفاده می‌کنید، حساب یا سازمان و سطح دسترسی را پیش از ایجاد مقصد مشخص کنید. عمومی بودن کد به معنی اعطای مجوز متن‌باز نیست؛ شرایط خدمات میزبان جداگانه اعمال می‌شوند.

## انتشار نسخه

برچسب v1.0.0 را فقط پس از موفقیت آزمون گیت‌هاب در مخزن مقصد ایجاد کنید. ZIP را با scripts/build_release.py بسازید و SHA-256 همان فایل را در یادداشت انتشار ثبت کنید. سازنده فایل‌های عمومی را صریح انتخاب می‌کند؛ local-data، حافظه‌های موقت، آرشیو خصوصی و بسته‌های تولیدشده کنار گذاشته می‌شوند. سلامت CRC فایل ZIP بررسی می‌شود و manifest دارای SHA-256 هر فایل است.

~~~bash
python scripts/build_release.py --out local-data/scf-mapping-toolkit-1.0.0.zip
~~~

متن پیشنهادی معرفی نسخه:

> نخستین نسخهٔ یکپارچهٔ ابزار محلی نگاشت و پشتیبانی ترجمهٔ فارسی؛ شامل ورود نسخهٔ ثابت SCF/AO، بازیابی یونیکد نامزدها، اعتبارسنجی تعهدهای مستقل بر اساس اصل منبع، خروجی تک‌برگهٔ Excel با تطبیق فایل ذخیره‌شده، ورود واژگان با تقدم افتا و آزمون‌های رگرسیون. تنها امتیاز صحیح ۵ تا ۱۰ قابل پذیرش است. داده‌های کامل مرجع ورودی محلی و خصوصی‌اند و توزیع نمی‌شوند. بررسی ماشینی صحت معنایی نگاشت یا انطباق حقوقی را تأیید نمی‌کند.

نتایج اندازه‌گیری‌شده را در [گزارش کنترل کیفیت](QA.fa.md) و qa/release-validation.json حفظ و با تغییرات جدید به‌روز کنید. درصد دقت بدون شاهد یا ادعای ممیزی مستقل همهٔ نگاشت‌های واقعی ننویسید. تغییر هر فایل عمومی نیازمند بازسازی manifest و بستهٔ انتشار است.
