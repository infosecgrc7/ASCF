# GitHub publishing guide

[راهنمای فارسی](PUBLISHING.fa.md)

The delivery is prepared locally. No repository creation, push or remote release is performed by the packaging scripts.

## Repository metadata

Suggested name: scf-mapping-toolkit

Suggested description:

> AO-aware regulatory-to-SCF mapping and Persian translation tools with source provenance, strict terminology filters and verified Excel exports.

Suggested topics: scf, strm, grc, cybersecurity, control-mapping, assessment-objectives, persian, translation, compliance

Use README.md as the landing page and README.fa.md as the Persian guide. The project is rights-reserved, not labelled open source. Do not select an MIT/Apache template for this repository unless the owner explicitly changes that decision.

## Before upload

1. Extract the final source ZIP into a new directory. Do not upload the surrounding working folder.
2. Run python -m pip install -r requirements.txt, then python -m unittest discover -s tests -q.
3. Run python scripts/audit_release.py. It checks local documentation links, package data boundaries, personal-path/account-link patterns and payload fingerprints when a manifest exists. This is a focused publication check, not a substitute for a security audit.
4. Run the documented synthetic validate/build/check commands. Use only fictional examples in the public repository.
5. Confirm LICENSE says all rights reserved and THIRD_PARTY_NOTICES.md remains present. Real inputs, translated SCF datasets and full books stay outside the uploaded payload.
6. Review repository visibility and the source text of the CI workflow. CI must actually run before claiming a remote platform pass.

## Upload

A GitHub web upload can use the extracted repository contents. For Git, initialize the extracted directory, add only the audited files, commit and push to the repository you create. Keep .gitignore intact. Do not initialize or push the original workspace containing local-data.

If using GitHub CLI, create the destination only after choosing the account/organization and visibility. Publishing this rights-reserved source does not grant open-source rights; hosting-platform terms apply separately.

## Release

Tag the version v1.0.0 only after CI passes in the destination repository. Use the source ZIP generated by scripts/build_release.py and record its SHA-256 in release notes. The builder selects public payload files explicitly and excludes local-data, caches, private archives and generated packages. It tests ZIP CRCs and includes a per-file SHA-256 manifest.

Suggested release summary:

> First integrated release of the local mapping and Persian translation workflow toolkit. Includes version-pinned SCF/AO import, Unicode candidate retrieval, source-grounded atomic-obligation validation, canonical single-sheet Excel export with saved-file reconciliation, AFTA-first terminology import and regression tests. Full reference datasets are private local inputs and are not distributed. Machine checks do not certify semantic mapping correctness or legal compliance.

Keep the exact measured validation results in docs/QA.md and qa/release-validation.json. Do not replace them with an unsupported accuracy percentage or a claim that every real-world mapping has been independently audited.
