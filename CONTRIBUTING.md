# Contributing

Project code is rights-reserved. Public availability is not a blanket permission to modify or redistribute it; obtain the rights holder's permission for contributions and derivative distributions. Do not infer a contributor license from this guide.

For authorized development, use Python 3.11+, install requirements.txt, run the unittest suite and audit_release.py. Keep fixtures synthetic. Add regression tests for observable defects, preserve source text, avoid automatic semantic approval and retain the fixed ten-column output contract. Do not add real regulatory documents, full SCF extracts, glossary books, credentials or account-specific links to a change.

A pull request should explain the concrete defect or behavior change, its data-contract impact and the verification actually run. Distinguish structural checks from model/human semantic review and keep both honest. Expand public claims only after a complete tested path exists.
